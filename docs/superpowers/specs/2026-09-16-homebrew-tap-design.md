# Homebrew tap inside the gitmole repository

Date: 2026-09-16. Status: approved in discussion, not yet built.

## Goal

`brew install gitmole` on macOS and on Linux with Homebrew, installing gitmole
and its three external tools in one step, with the formula kept in this
repository and bumped by the existing release workflow.

## Decisions

- **Single repository.** The formula lives at `Formula/gitmole.rb` here. There
  is no `homebrew-gitmole` repository and no cross-repository token. Users tap
  with the URL form once, then use the short name:

  ```
  brew tap antvinni/gitmole https://github.com/antvinni/gitmole
  brew install gitmole
  ```

  The one-line `brew install antvinni/gitmole/gitmole` form does not work
  without a `homebrew-` prefixed repository and is not offered.
- **The formula installs a release, not main.** `url` is the sdist the
  release job already attaches to each GitHub release
  (`https://github.com/antvinni/gitmole/releases/download/vX.Y.Z/gitmole-X.Y.Z.tar.gz`),
  with its sha256. `head` points at the git repository for `brew install --HEAD`.
- **Python dependencies are pinned resources.** The formula uses
  `Language::Python::Virtualenv`, `depends_on "python@3.14"` (Homebrew's
  current Python), and one resource stanza per Python package gitmole needs at
  runtime: `rich`, `lizard`, and rich's `markdown-it-py`, `mdurl`, `pygments`.
  The stanzas are generated by `brew update-python-resources`, never typed by
  hand. The plots extra (git-of-theseus) is not part of the formula.
- **External tools are formula dependencies:** `scc`, `git-sizer`, `gitleaks`.
- **The formula is tested in CI.** A `formula` job in the existing workflow
  runs on pull requests and pushes to main, on macOS: tap the checkout, `brew
  audit --strict`, `brew install --build-from-source`, `brew test`. It installs
  the stable release the formula points at, so it checks the formula, not the
  branch's Python code; the `test` job already covers that.
- **The release job bumps the formula after the release exists.** After the
  GitHub release is created, the job rewrites the `url` and `sha256` lines to
  the sdist it just built, reruns `brew update-python-resources` so the
  resource stanzas track the dependencies, verifies the formula installs and
  passes `brew test`, and commits `Formula/gitmole.rb` to main. Ordering:
  release first, commit second, so a `brew update` never sees a formula whose
  tarball does not exist. The release job therefore moves to a macOS runner,
  where Homebrew is present.
- **The formula's own test** checks `gitmole --version` prints the formula's
  version and that a report on a one-commit repository runs and mentions the
  commit count.
- **README** leads the Install section with the brew commands on macOS and on
  Linux with Homebrew; pipx stays as the alternative. The Principles section
  is unchanged.
- **v0.2.3** is tagged once both PRs are in, to exercise the bump end to end.
  Its first automated commit to main is the acceptance test of this work.

## Non-goals

Homebrew core submission (a later step once the project has users); bottles
(a pure-Python build installs in under a minute); a Linux package; supporting
Homebrew Pythons other than the current one.

## Risks accepted

- Homebrew moves its default Python roughly yearly; the `formula` CI job will
  fail when `python@3.14` is removed from core, which is the signal to bump.
- `brew audit --strict` rules change over time; same signal.
- The release job committing to main means a tag produces two commits on
  main: yours (the version bump) and the workflow's (the formula bump).
