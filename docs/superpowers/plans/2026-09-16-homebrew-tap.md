# Homebrew Tap Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `brew tap antvinni/gitmole https://github.com/antvinni/gitmole && brew install gitmole` installs gitmole with scc, git-sizer and gitleaks, from a formula kept in this repository and bumped automatically by the release workflow.

**Architecture:** `Formula/gitmole.rb` is a Homebrew Python-virtualenv formula pointing at the sdist attached to each GitHub release, with pinned resource stanzas for the Python dependencies. The existing CI workflow gains a `formula` job (audit, install, test) and the release job gains a step that rewrites the formula for the new release and commits it to main after the release exists.

**Tech Stack:** Homebrew 7 (`Language::Python::Virtualenv`, `brew update-python-resources`, `brew audit`, `brew test`), GitHub Actions on macOS runners, `gh`.

**Spec:** `docs/superpowers/specs/2026-09-16-homebrew-tap-design.md`

## Global Constraints

- The formula's `url` is the release sdist `https://github.com/antvinni/gitmole/releases/download/vX.Y.Z/gitmole-X.Y.Z.tar.gz`, never a GitHub `archive/` tarball and never main.
- `depends_on "python@3.14"`, `"scc"`, `"git-sizer"`, `"gitleaks"`. Resource stanzas are generated with `brew update-python-resources`, not typed.
- No token, no second repository. The release job commits to main with the workflow's own `GITHUB_TOKEN`, after `gh release create` has succeeded.
- Every commit message: subject, blank line, `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.
- This machine has `/opt/homebrew/bin/gitmole` as a symlink to `bin/gitmole` in this checkout (the developer install). `brew install gitmole` refuses to link over it. Every local verification that installs the formula must end by uninstalling it and restoring the symlink: `brew uninstall gitmole; ln -sfn "$PWD/bin/gitmole" "$(brew --prefix)/bin/gitmole"`, and `brew untap antvinni/gitmole`. Installing the formula also installs `python@3.14`, which puts a `python3` without rich or lizard first on PATH and breaks both the developer install and the test suite; when the machine did not have it before, finish with `brew uninstall python@3.14` as well.
- `python3 -m unittest discover -s tests -t .` must still print OK before each commit (nothing here touches Python code, but the README and workflow live in the same tree).

```ruby
class Gitmole < Formula
  include Language::Python::Virtualenv

  desc "Offline git repository analysis with a terminal report"
  homepage "https://github.com/antvinni/gitmole"
  url "https://github.com/antvinni/gitmole/releases/download/v0.2.2/gitmole-0.2.2.tar.gz"
  sha256 "a3d4af49711f816860110407b0e5fb28afc92fd7e26d0e22cbf3f7fb840c3e23"
  license "MIT"
  head "https://github.com/antvinni/gitmole.git", branch: "main"

  depends_on "git-sizer"
  depends_on "gitleaks"
  depends_on "python@3.14"
  depends_on "scc"

  # resources: generated by `brew update-python-resources antvinni/gitmole/gitmole`

  def install
    virtualenv_install_with_resources
  end

  test do
    assert_match "gitmole #{version}", shell_output("#{bin}/gitmole --version")
    system "git", "init", "-q", "repo"
    (testpath/"repo/a.py").write "x = 1\n"
    system "git", "-C", "repo", "add", "a.py"
    system "git", "-C", "repo", "-c", "user.name=t", "-c", "user.email=t@x", "commit", "-q", "-m", "one"
    output = shell_output("#{bin}/gitmole repo --out out --markdown - 2>/dev/null")
    assert_match "1 commits", output
  end
end
```

### Task 2: The `formula` CI job

**Files:**
- Modify: `.github/workflows/ci.yml` (add a job after `test`)

**Interfaces:**
- Produces: a job named `formula` that fails the PR when the formula does not audit, install or test.

- [ ] **Step 1: Add the job**

Insert after the `test` job, before `release`:

```yaml
  formula:
    name: homebrew formula
    runs-on: macos-latest
    steps:
      - uses: actions/checkout@v4
      - name: Tap this checkout
        run: brew tap antvinni/gitmole "$PWD"
      - name: Audit
        run: brew audit --strict --online antvinni/gitmole/gitmole
      - name: Install from source
        run: brew install --build-from-source antvinni/gitmole/gitmole
      - name: Test
        run: brew test antvinni/gitmole/gitmole
```

Also make `release` wait for it: `needs: [test, formula]`.

### Task 3: The release job bumps the formula

**Files:**
- Modify: `.github/workflows/ci.yml` (`release` job)

**Interfaces:**
- Consumes: `dist/gitmole-X.Y.Z.tar.gz` built earlier in the job; the formula's `url` and `sha256` lines in the exact shape Task 1 wrote them (two-space indent, one line each).
- Produces: a commit `Homebrew formula: vX.Y.Z` on main after each release.

- [ ] **Step 1: Move the release job to macOS and add the bump step**

Change `runs-on: ubuntu-latest` to `runs-on: macos-latest` in the `release` job (Homebrew is needed for the resource update and the verification). Change the checkout step to fetch main too, and append the bump step after "Create the GitHub release with the artefacts":

```yaml
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      ...
      - name: Bump the Homebrew formula to this release
        env:
          GH_TOKEN: ${{ github.token }}
        run: |
          set -euo pipefail
          VERSION="${GITHUB_REF_NAME#v}"
          SDIST="dist/gitmole-${VERSION}.tar.gz"
          SHA="$(shasum -a 256 "$SDIST" | cut -c1-64)"
          git config user.name "github-actions[bot]"
          git config user.email "41898282+github-actions[bot]@users.noreply.github.com"
          git fetch origin main
          git checkout -B main origin/main
          sed -i '' \
            -e "s|^  url \".*\"$|  url \"https://github.com/antvinni/gitmole/releases/download/${GITHUB_REF_NAME}/gitmole-${VERSION}.tar.gz\"|" \
            -e "s|^  sha256 \".*\"$|  sha256 \"${SHA}\"|" Formula/gitmole.rb
          git commit -am "Homebrew formula: ${GITHUB_REF_NAME}"
          brew tap antvinni/gitmole "$PWD"
          brew update-python-resources antvinni/gitmole/gitmole
          cp "$(brew --repo antvinni/gitmole)/Formula/gitmole.rb" Formula/gitmole.rb
          git diff --quiet || git commit -am "Homebrew formula: ${GITHUB_REF_NAME}" --amend --no-edit
          git -C "$(brew --repo antvinni/gitmole)" reset --hard -q
          git -C "$(brew --repo antvinni/gitmole)" pull --ff-only "$PWD" main
          brew audit --strict --online antvinni/gitmole/gitmole
          brew install --build-from-source antvinni/gitmole/gitmole
          brew test antvinni/gitmole/gitmole
          git push origin main
```

Notes for the executor: the `git commit -am` before the resource update is deliberate, because `brew tap` clones the committed state; the `reset --hard` discards the tool's edit inside the tap clone after it has been copied out, so the tap can fast-forward to the amended commit. The `sed -i ''` form is BSD sed, which is what the macOS runner has.
